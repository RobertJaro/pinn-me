# MURaM synthesis and validation

Synthetic Stokes data are generated by the independent depth-marching reference
solver in `prom3theus.validation.reference_synthesis`. The production inversion
uses atmosphere predictions followed by parallel formal LTE integration. The `synthesize`
command generates independent validation data for checking the production
formal solver and atmospheric recovery.

Use Python 3.11+ with PROM3THEUS and its `observations` dependencies installed.
The synthesis command now defaults to **HMI + AIA FITS**:

```bash
PYTHONPATH=src python -m prom3theus.muram.cli synthesize \
  --source-path data/muram --iterations 200000 --out /tmp/muram-sdo \
  --batch-size 256
PYTHONPATH=src python -m prom3theus.muram.cli validate-config configs/muram/sdo/joint.yaml
```

For each snapshot it writes:

- `hmi/prepared/hmi.S_720s.<time>_TAI.3.I0.fits` through `V5.fits`: 24 segments
  in HMI's red-to-blue filter order, with physical spectral radiance, WCS, time,
  and explicit synthetic-product metadata. The I0 binary tables preserve the
  exact wavelength quadrature, filter weights, and parallel-ray geometry.
- `hmi/responses/hmi.S_720s.<time>_TAI.3.response.npz`: the exact synthetic
  transmission profile used for that acquisition, with float64 wavelength nodes
  and float32 spectral/continuum weights in increasing wavelength order. The
  run configuration loads this directory directly. Profiles are explicitly
  synthetic; no observational phase-map identity is fabricated. Training checks
  them against the response embedded in I0 and rejects missing or mismatched files.
- `aia/fits/aia.lev1_euv_12s.<time>.<channel>.fits`: all three packaged training
  channels, **171, 193, 211 Å**, in reference-response DN/s per AIA reference pixel.

After all snapshots, the saved AIA FITS are prepared into `aia/prepared` using the
same calibrated image-store boundary used for observed SDO training. The ordinary
`hmi_stokes` loader reads the synthetic HMI FITS directly; the ordinary `aia_euv`
loader reads that prepared AIA store. Synthetic radiometry is known, so HMI does
not fit an observational quiet-Sun gain and AIA uses unity degradation. These are
marked synthetic reference products, not raw detector DN or observed phase maps.
The HMI training loader divides the physical FITS radiance by the same packaged
disk-center atlas continuum as observed HMI (about 3.1585e13 W m^-3 sr^-1).
The internal synthesis scale, 1e13, is only a numerical transfer unit. Earlier
synthetic loaders also used it as the training unit, inflating amplitudes by
3.1585 and MSE by 9.976 for identical physical residuals. Rebuild preparation
caches and start a fresh training run after this normalization fix; the physical
FITS and transmission profiles do not need regeneration for this fix alone.
Do not run observed Level-1 aiapy pointing/degradation processing on these files.

Both formats carry the existing flat MURaM geometry exactly. It is centered at
Carrington longitude 0°, latitude 0°, with radial direction along Carrington x.
FITS WCS is a visualization embedding. Training uses the embedded parallel-ray geometry rather than replacing
it with a perspective WCS ray. The synthetic epoch is **2010-03-24 00:00 UTC**;
simulation seconds are added to this epoch, with explicit UTC/TAI conversions.
Local co-rotating MURaM velocities include the projected Carrington rotation in
synthesized spectra, matching the training forward model for a stationary observer.
Regenerate older polar-embedded FITS and profiles to use the equatorial geometry;
changing only FITS latitude headers would leave the embedded coordinates inconsistent.

Progress counts selected columns. `--stride N` selects `[::N, ::N]` before
resampling and synthesis, with no averaging. It defaults to `None`. `--binning N` (also `-binning N`) averages N×N
blocks after synthesis, preserving mean radiance/intensity. Used alone, it
synthesizes every native column. If both options are supplied, stride selects
columns first and binning averages the synthesized output. Dimensions after
stride must be divisible by N; incomplete blocks are rejected. The shell
scripts preserve native resolution (neither stride nor binning). Output pixel spacing increases by the binning factor,
and geometry uses block centers. Coordinates retain native sample locations, including
for non-divisible dimensions. SDO synthesis computes HMI and AIA from each batch,
then saves their FITS products after the snapshot pass completes. Raw Stokes spectra
are released after writing HMI; all native fields are released before loading
the next snapshot. `synthesis_status.json` records the current stage and completed
snapshots. Existing output directories are resumed: completed snapshots are
skipped, and interrupted snapshots are regenerated from the beginning (there is
no within-snapshot batch checkpoint). Batch size and device may change on resume;
changes to recorded synthesis settings require a new output directory or
`--overwrite`. The `--overwrite` flag replaces the entire output directory.
Source files are read-only. Completed FITS remain available if a later stage fails.

### Loading and evaluation resolution

Synthesis output is the reusable native-resolution source. The MURaM inversion
presets set `streams[].observation.binning: 4` to average 4×4 saved pixels when
loading Hinode stores, synthetic HMI FITS, and prepared synthetic AIA stores.
Omit this option or set it to `1` to use the saved resolution. The option must
be a positive integer and both spatial dimensions must be divisible by it.
It applies to the **saved** grid: for existing products already synthesized
with `--binning 4`, use loading `binning: 1` to retain the previous resolution.
New native products require a new synthesis output directory or explicit
`--overwrite`; resume rejects changes to recorded synthesis settings.

Loading averages calibrated Stokes/intensities before per-profile normalization,
places rays at block centers on the spherical embedding, and averages auxiliary
reference maps when loading older stores that contain them. A block is valid only if every contributing
pixel is valid. Source metadata retain the synthesis resolution; separate
`spatial_binning` metadata describe the loading reduction and output spacing.
Native files remain unchanged. Binning is part of the prepared-data identity;
change it with fresh work/output directories or explicitly rebuild observations
rather than resuming a different-resolution data module/checkpoint.
AIA objective scales are recalculated from the binned, selected observations.
This loading option currently supports synthetic MURaM data only.

For a comparison of native predictions with binned observations, use
`prom3theus.muram.binning.bin_spatial(predicted_stokes, factor)` before computing
nonlinear normalization or diagnostics. Apply the same reduction to reference
maps. The helper preserves tensor gradients. The inversion retains the existing
single-ray-at-block-center approximation; this change does not add subpixel
radiative transfer. Averaging atmospheric parameters or inferred fields is not
equivalent to averaging synthesized profiles.


For FITS generated before standalone transmission profiles were added, export
them without repeating synthesis:

```bash
PYTHONPATH=src python -m prom3theus.muram.cli prepare-responses \
  --source-path /path/to/sdo/hmi/prepared --out /path/to/sdo/hmi/responses
```

This reads the lossless response already embedded in each synthetic I0 FITS.
Existing profile files are not overwritten. Older configurations pointing the
response directory at `hmi/prepared` continue to use the embedded response.

`scripts/muram/run_inversion.sh` now uses `configs/muram/sdo/joint.yaml`,
which follows the standard SDO HMI+AIA dynamic-energy training configuration.
Set `MURAM_SDO` to select the observation root; set output and work directories
in the YAML. The SDO presets are grouped under `configs/muram/sdo/`:
`joint.yaml` enables HMI+AIA and physics, `mhs.yaml` uses HMI with MHS constraints,
and `stokes_only.yaml` provides the likelihood-only control.
The default AIA validation group is `muram_000000`; change it when starting at
another iteration. There is no hard-coded observed-data time window. This is a
production-sized training configuration, not a short smoke test.

The older single-instrument path is retained with **`--output-format store`**.
It writes incremental Stokes ObservationStores or diagnostic AIA NPZ files.
These require a separate `muram_stored` inversion configuration; the default
`configs/muram/sdo/joint.yaml` now expects HMI+AIA SDO products. Custom
instrument YAML currently requires this explicit legacy output format.

## Runtime and performance

### Equivalence to observational training

This applies to `configs/muram/sdo/joint.yaml` with the default `sdo-fits`
products. The retained legacy `muram_stored` format is a separate contract.
The current synthetic and observed dynamic-energy presets share the atmosphere,
physics, optimizer, loaders, both data terms, component/stream weights, and depth
sampling. Both use float32 forward computation with float64 wavelength setup.
HMI uses fixed atlas-continuum units and AIA uses reference-response DN/s/pixel.
No synthetic-only loss multiplier or per-pixel continuum normalization is applied
during data preparation. The optional `observed_continuum` likelihood normalization
uses the same fixed, floored observed outer-filter mean for prediction and target.
Those filters are a continuum proxy, not a line-free continuum measurement.

| Stage | Synthetic MURaM | Observed SDO |
| --- | --- | --- |
| HMI radiometric calibration | SI radiance is known; divide by the packaged atlas continuum | Fit one detector gain from quiet-Sun pixels, then divide by the same atlas continuum |
| HMI spectral response | Uniform idealized Gaussian filters, exact quadrature/weights exported with each acquisition | Spatially varying measured phase-map responses |
| Geometry | Equatorial rectangular patch, parallel rays, embedded scene/Stokes basis | WCS-derived perspective rays and spatially varying projection |
| Velocity frame | Local co-rotating flow plus Carrington rotation; stationary synthetic observer | Same co-rotating-to-inertial conversion, with measured spacecraft LOS velocity subtracted |
| AIA preparation | Already registered reference-response count rates; unit exposure and unity degradation | Exposure normalization, pointing/registration and detector-degradation calibration precede the same prepared-image boundary |

Both MURaM inversion presets fix the instrumental LOS velocity correction to
zero (`optimize_line_of_sight_velocity_correction: false`). Native simulation
flows remain in the synthesized spectra and the inferred velocity field is
still trainable. When resuming with correction fitting disabled, the Stokes
term restores the configured fixed offset instead of a previously learned
checkpoint offset. The optimization switch may change on resume; the configured
calibration value remains part of the scientific compatibility contract.

For failure-to-fit diagnosis, `configs/muram/sdo/stokes_only.yaml` provides a
Stokes-only control in separate `muram_stokes_only_uniform192_v03`
directories. It uses the original 256-wide, eight-layer SIREN with
`first_omega_0: 5.0` and `hidden_omega_0: 1.0`. The I/Q/U/V weights are
1/200/200/200, increasing polarization weights tenfold from the original control.
The depth audit found the old 25+16 grid under-resolved. This control now uses
128 coarse plus 64 adaptive points, `height_sampling: uniform`,
`randomize_training: false`, and a batch of 64 pixels to keep the number of
atmosphere evaluations per batch comparable. Uniform physical-height spacing
provides approximately 20 km coarse resolution throughout the line shell;
the earlier FALC-shaped grid left depressed umbral formation layers sparse.
See [the HMI ray audit](hmi-ray-sampling-audit.md) for coverage and accuracy tests.
This is a starting resolution for a convergence check, not a universal accuracy
guarantee. The observation geometry and vector-potential representation remain
unchanged. Separate directories start a fresh comparison. The control
disables all physics and potential penalties, adaptive balancing, and the AIA
likelihood. AIA remains available for geometry and evaluation diagnostics;
zero-weight streams skip forward synthesis during training. Data preparation
and batch loading still retain those streams. Run the control
with `python -m prom3theus.muram.cli invert configs/muram/sdo/stokes_only.yaml` and
`PYTHONPATH=src`. An existing checkpoint in that control directory will still
auto-resume; use a fresh directory for an initialization experiment.

Online training and validation logs include `component_mse.I/Q/U/V` in
objective units, before component and stream weights, and
`stokes_Q_raw_residual_rms` (also I/U/V) in fixed atlas-continuum units before
loss transforms. Validation also reports outgoing Stokes admissibility.
The **Stokes individual profiles**
panel shows signed raw profiles for the largest observed Q/U, largest V, and
lowest mean I in the bounded validation sample. Ensemble medians can cancel
opposite-polarity or opposite-azimuth signals even when the individual profiles
contain substantial polarization.
| AIA objective scale | Robust per-channel scale derived from synthetic valid pixels | Same algorithm derived from observed valid pixels; numerical scales need not match |
| Noise and resolution | No detector noise, additional spatial PSF, or temporal averaging; stride selects native columns, optional binning averages synthesized pixels | Instrument resolution, exposure averaging, noise and artifacts remain in the measurements |
| Validity masks | Finite synthetic samples; generated quality flags and on-disk masks | Measured quality flags, finite samples, WCS/on-disk masks |
| Time and validation selection | Synthetic epoch plus simulation time; all saved times; `muram_000000` validation group | Observational timestamps, configured time window and exposure group |
| Forward-generation approximation | HMI uses all native MURaM vertical cells; AIA integrates native cell widths with a tau<=1 visibility proxy | Observations are measurements, not generated by this LTE/optically thin model |

The inversion of either dataset uses the same 25+16 LTE depth samples and 32+32
AIA ray samples. Different synthesis/inversion quadratures and a finite simulation
box can therefore leave residuals even with perfectly matched units. Synthetic
AIA assumes equilibrium EOS/emissivity and does not model EUV absorption. The
spherical geometry and boundary/energy priors are shared inversion assumptions,
not exact representations of the Cartesian simulation's boundary conditions.

Regression checks compare known physical HMI profiles passed through synthetic
FITS loading and ordinary detector-gain calibration, including the resulting
MSE and gradients. AIA checks compare unity-degradation inputs with known degraded
inputs at the common registered-image preparation boundary. These verify the
data contract; they do not establish that a real observational calibration is
error-free or that synthetic and observed scenes should have equal fitted losses.

Batch size defaults to **256 native columns**. `--device auto` now selects one
visible CUDA GPU, otherwise CPU, matching the training device selector. The
startup message and progress bar show the resolved device, dtype, and batch size.
Use `--device cuda` inside a GPU allocation to fail immediately if CUDA is not
available, or `--device cuda:1` to choose another visible GPU. CPU reading and
interpolation remain on the host; atmosphere batches, instrument operators,
EOS/opacity tables, and radiative transfer use the selected device. Results return
to CPU for storage. This command does not distribute batches across multiple GPUs.

Native snapshot loading uses a dataset indexed by flattened horizontal pixels
(`index = x * ny + y`). A DataLoader with **two persistent CPU workers** opens
read-only memory maps lazily in each worker, reads full-depth columns and
converts each column in place after copying it. `--batch-size` controls both
loading and synthesis batches. One batch is prefetched per worker; synthesis
itself remains sequential. Worker processes receive filenames and geometry
metadata, never serialized cube contents. There is no tile cache or tile-size
option. Flattening is logical indexing, so it does not copy the oriented cube.
Results are assembled back into the original 2D pixel map.
Snapshots listed in `--iterations` remain in a sequential for loop: each is
synthesized and saved, then its workers are stopped before the next is loaded.

The axis mapping and optical-depth orientation are computed once per snapshot;
orientation reads only the two native tau boundary planes. A single pass through
selected flattened pixels loads each column batch once. HMI and AIA in the SDO
command process each loaded batch sequentially before advancing to the next batch.
Only output spectra and geometry are retained, not native cubes. No overview,
ground-truth map, or continuum optical-depth check is computed.
All native columns are retained unless `--stride` is explicitly requested.
Physical units, wavelength sampling, and binning are unchanged. All native
vertical layers are used without resampling or an optical-depth cutoff.

Batch size is not a total process-memory limit: output spectra, geometry,
transfer intermediates, prefetched batches, and OS file-cache pages also consume
memory. The Python `synthesis_ready_quantities()` API still
explicitly materializes full converted arrays; the CLI and synthesis functions
use `synthesis_columns()` instead. Python callers can call `snapshot.close()`
after their last synthesis to release its workers and mappings. The CLI does
this automatically between iterations and on failure. Batch size may change
when resuming a run.

The old implementation never moved any tensors or modules to CUDA. It also did
more work than the training configuration: float64 and 193 depths, compared with
float32 and 25 coarse + 16 fine samples in the validation inversion. Synthesis
now defaults to float32; `--dtype float64` provides a reference comparison.
Vertical resolution is the native MURaM cell spacing; there is no synthesis
`--depth-samples` option.

The previously measured 0.65% Stokes-I discrepancy was a spectral-grid bug:
constructing absolute wavelengths near 6173 Å in float32 quantized quadrature
nodes and filter centres, shifting samples by up to 23 m/s and changing filter
weights. Calibration wavelengths now remain float64 through spectral setup.
The backend then caches small Doppler offsets in km/s, and the instrument caches
response weights/interpolation fractions, in the selected runtime dtype. Training
uses the same preparation strategy for both HMI and Hinode. Forward and backward
remain float32; high-precision calibration is a one-time setup operation.

On the original 16-column, iteration-200000 CPU cutout at 193 depths, the maximum
filtered float32/float64 differences are now 0.00096% of local Stokes I for HMI
and 0.0012% for Hinode. Unfiltered differences remain below 0.0026% of Stokes I.
These are measured cases, not a universal precision bound. The remaining error
is dominated by the float32 polarized formal solution. Depth convergence,
atomic/EOS assumptions and instrument-response approximations are separate checks.

The Planck function also uses micrometres and a 1e13 radiance reference to avoid
cancelling large SI logarithms. Training ray intersections and refined heights
use local distances instead of subtracting solar radii. For a disk-centre and
oblique-ray test, float32 height differences fell from 91 m to under 1 m.
Vector-potential/potential-plus-residual decoding preserves those heights while
computing Cartesian field derivatives about a local origin.

Regenerate old synthetic observations and rebuild preparation caches to benefit
from the corrected metadata. Wavelength precision lost in an existing float32
store cannot be recovered by casting that store to float64. Callers constructing
custom grids should likewise supply float64 wavelengths before preparation.

New Stokes products record `muram_synthesis.forward_model_provenance` in the
FITS `CONTRACT` table and legacy observation-store metadata. This includes a
versioned numerical contract plus SHA256 identities for the RT implementation,
native-column conversion, instrument operator, line data, abundances, and EOS/
opacity tables. Loading a product without this identity emits a legacy warning;
loading one with different code or resources emits a mismatch warning. Both
remain loadable, while a corrupt provenance fingerprint is rejected. The check
also runs on observation-cache hits, so an old prepared cache cannot silently
claim closure with a changed forward model. Source hashes are conservative:
comment-only changes can trigger a mismatch, which requires a matched-atmosphere
comparison or regeneration rather than establishing a physical error by itself.

Interpolation now searches for depth brackets once per column and reuses that
plan for every field, replacing repeated full-depth scans. A 256-column
resampling probe decreased from about 0.21 s to about 0.01 s after warmup.
The radiative-transfer calculation remains the main cost. At the defaults, one
256-column batch's single 4×4 propagation-matrix tensor alone occupies about
0.48 GiB; other intermediates also consume memory. Reduce `--batch-size` if the
selected GPU runs out of memory.

A 512×256 snapshot with `--stride 4` synthesizes only 128×64 = 8,192 columns
(32 batches at the default size), reducing the column synthesis work by 16×.
With `--binning 4` instead, all 131,072 columns are synthesized (512 batches),
then averaged to 128×64 output pixels. Progress counts synthesized columns.
Native columns are loaded by CPU workers as the sequential transfer loop advances.
Store mode identifies native source files using their resolved paths, sizes,
and nanosecond modification/change timestamps. It does not read the full cubes
for hashing before synthesis. This metadata signature is not a content checksum;
the forward-model code/resource provenance and saved-array checksums remain intact.

## Other packaged instruments

The Python API `synthesize_stokes(snapshot, instrument=..., line_ids=...,
observed_wavelength_angstrom=..., response=...)` uses the common instrument
factory. It supports all registered LTE operators, currently HMI and Hinode/SP.
The stored observation adapter reads the instrument and spectral contract from
the output, so it also supports Hinode stores. Match the inversion data term's
instrument, line IDs, and PSF to the synthesis settings.

Pass `--instrument-config path/to/synthesis.yaml` to select these options on the
CLI. For example, this generator creates a Hinode/SP configuration:

```python
import numpy as np
import yaml

options = {
    "instrument": {
        "type": "hinode_sp",
        "spectral_psf": {
            "type": "gaussian", "fwhm_angstrom": 0.03,
            "oversample": 4, "truncate_sigma": 4.0,
        },
    },
    "line_ids": ["FeI_6301.5008", "FeI_6302.4932"],
    "observed_wavelength_angstrom": np.linspace(6301.0, 6302.9, 96).tolist(),
}
with open("/tmp/muram-hinode.yaml", "w") as handle:
    yaml.safe_dump(options, handle)
```

Custom HMI synthesis uses `type: hmi_filter_profiles`, its quadrature grid,
`inner_half_width_angstrom`, and `magnetic_azimuth_offset_deg: 90`. Supply uniform
`response.spectral_weights` and `response.continuum_weights`; these are persisted
with the observations. The default HMI wrapper uses 161 quadrature nodes and
76 mÅ Gaussian filters, not calibrated phase maps.

The packaged AIA response is available through `synthesize_aia`, or this CLI YAML:

```yaml
instrument:
  type: aia_euv
  channels_angstrom: [171, 193, 211]
  response_resource: aia_euv_v1:aia_temperature_response
```

In `--output-format store` mode, AIA writes one NPZ **diagnostic image** per snapshot, with intensity, channels,
spacing, time, and response-resource identity. These are not prepared AIA
inversion stores. Intensities remain DN/s per reference AIA pixel: horizontal
striding selects native intensities without multiplying detector pixel area.

## Physical conventions and limits

The user's `MHD_Induction/mhd/data/read_muram.py` uses fixed component
labels independently of storage transposes. Those labels are not sufficient
to determine the physical component alignment of every export. For the local
full snapshot at iteration 200000, native components 5/6/7 follow header axes
0/1/2: a fourth-order divergence check gives a normalized residual of 0.000126,
versus 0.61 when components 5 and 6 are swapped. Thus primitive 6 is vertical
for this snapshot. The default `--component-order 0 1 2` uses this alignment.
`--component-order` lists the raw component indices aligned with original header
axes 0, 1, 2, independently of any storage transpose. For this header,
`--component-order 1 0 2` reproduces the reference reader's fixed labels; use
that override only for exports whose physical alignment has been verified.

The header gives output shape (512,256,768) and spacing (192,192,64) km.
The density-only `data/muram_example` confirms vertical storage axis 1 but
cannot establish magnetic component alignment. Reproducible local audits are
in `data/muram_units_audit`. Data synthesized with the previous forced
primitive-5-as-vertical mapping must be regenerated, and training restarted.

The unit audit on 64 sparse columns of local iteration 200000 found no extra
MURaM normalization to apply. Native cell widths are 192/64/192 km. Native
pressure converts by 0.1 to Pa, mass density by 1000 to kg/m³, velocity and
length by 0.01 to SI, and magnetic fields by sqrt(4 pi) to gauss. At native tau≈1,
median pressure was 6.805 kPa and density 2.089e-4 kg/m³; the LTE EOS/native
density ratio was 0.9914–0.9969. Synthesized outer-wavelength Stokes I divided
by the atlas continuum ranged from 0.263 to 1.799, with median 1.132. This is a
sparse-snapshot check, not a bound on all times or pixels.

The Planck source is spectral radiance in W m^-3 sr^-1 (per metre wavelength),
not flux. It agrees with Astropy's independently evaluated blackbody to 2e-15
relative error in float64. Normalized HMI filter averaging preserves that unit;
neither a pixel-area factor nor an extra pi belongs in this conversion. FITS
restores the internal 1e13 transfer scale once; training then divides by the
atlas reference once. AIA uses ne in m^-3 and path length in metres, so its
cm^5 response requires the 1e-10 emission-measure conversion; independent SI
and CGS evaluations agreed to 6e-16 in float64. Regression tests anchor native
CGS fields and Planck radiance independently of the reader conversion constants.

- Binary cubes have the first header axis varying fastest. By default vector
  components follow header axes. For the checked snapshot, synthesis uses
  primitive velocities (1,3,2) and magnetic fields (5,7,6), with the second
  spatial axis and vector component reflected to preserve handedness.
  Converted magnetic fields remain gauss after multiplying by sqrt(4*pi).
  These files must contain primitive velocities, not momentum densities.
- The finest-spaced header axis is vertical. `--vertical-axis` provides an
  explicit storage-axis override for tied/isotropic spacing. Tau determines
  which end of that axis is the top, not which component is vertical.
  Spatial transpositions/reflections and vector mappings preserve handedness.
- Columns are vertical, viewed along parallel rays with a common Stokes basis.
  Transfer uses all native vertical cells, their physical spacing, and the
  packaged LTE opacity. No log-tau interpolation or opacity-based trimming is
  performed. The two tau boundary planes determine orientation; internal tau
  labels are not used for Stokes synthesis.
- The HMI 90-degree azimuth convention is applied before synthesis. Positive
  upward velocity is toward the observer and therefore produces a blueshift.
  No unresolved microturbulence, instrumental noise, or spatial PSF is added.
- The spherical inversion embeds the flat box into an equatorial scene chart.
  This is a local approximation, not an exact mapping of Cartesian MHD into a
  curved solar shell. The 49.152 megameter domain length in Header.200000 does not specify
  the height of tau=1. The YAML's 50 megameter upper shell and potential/open boundary
  terms are priors, not measured MURaM boundary conditions. HMI alone cannot
  establish recovery of the full coronal atmosphere or transverse velocities.
- AIA integrates `ne(T,P)^2 K(T) dz` over full cell widths at selected strided columns.
  Its EOS and response assume equilibrium. Native tau<=1 is only an approximate
  photospheric occultation mask; EUV absorption, non-equilibrium ionization and
  optically thick chromospheric emission are not modeled. See the
  [CHIANTI response documentation](https://www.chiantidatabase.org/cug.html).

Stokes synthesis uses the full native column, from the bottom cell to the top
cell, at native vertical resolution. Each batch is reordered top to bottom for
transfer, with path lengths derived from the header's vertical cell spacing.
No `log_tau500_grid`, depth resampling, continuum optical-depth check, or automatic
extension is used. The top layers are retained as well. Metadata record the
native layer count and vertical cell spacing. The transfer solver uses its
Planck lower boundary at the bottom native cell.

For historical depth-convergence measurements at the old fixed bounds: on a
2×2 native-column cutout of iteration 200000, 25 versus 97 levels changed the
maximum signal by 2.1% of Stokes I; 193 versus 385 differed by 0.03%. These are
local checks, not full-snapshot error bounds.

Depth and wavelength convergence still need assessment for each scientific run,
especially flare columns. Increasing spectral/depth sampling cannot remove the
LTE, equilibrium, finite-resolution, or inversion-degeneracy assumptions.


## Native column ordering

The reader orients native z upward using the two tau boundary planes. Synthesis
reverses the loaded cells into top-to-bottom transfer order without sorting or
interpolating their values. Native temperature, pressure, magnetic field, and
velocity are preserved. Geometric spacing must be positive and columns must
contain at least two layers. Atmospheric values must be finite, with positive
temperature and gas pressure.
