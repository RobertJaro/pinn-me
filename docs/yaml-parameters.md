# YAML parameter review

There are nine inversion presets under `configs/` and one instrument file for MURaM synthesis. The tables cover the keys present in those files. For an inversion, `load_config(path).to_dict()` also shows the defaults supplied by schema v5. When inspecting a `muram_stored` preset from Python, import `prom3theus.muram.config` first to register its observation type. The MURaM CLI does this automatically.

## Model and observations

| YAML section | Parameters | Effect |
| --- | --- | --- |
| Run and scene | `schema_version`, `solver.kind`, `output_directory`, `work_directory`, `scene.reference_stream`, `time_window.start/end` | Version 5 selects the joint format. The two directories separate published state from prepared data and diagnostics. The reference stream establishes the coordinate and time frame. The optional UTC window selects exposures. |
| Atmosphere geometry | `type`, `time_dependent`, `height_input_scale_m`, `uniform_spatial_scaling`, `inner_height_megameter`, `outer_height_megameter`, `line_formation_outer_height_megameter`, `tangent_margin_m` | Define the spherical domain, network coordinates, LTE region and ray geometry. The outer shell also bounds EUV integration. The tangent margin is used when tracing height-grid rays for atmospheric diagnostics and export. |
| Atmosphere state | `reference_atmosphere`, temperature, gas-pressure and microturbulence `log_scale`, velocity `scale_m_per_s`, magnetic `scale_gauss`, `representation`, `scale_vector_potential` | Set the reference stratification and neural output scales. The vector-potential multiplier acts on the potential before taking its curl. |
| Network and upper atmosphere | `network.type`, `hidden_dimension`, `hidden_layers`, `first_omega_0`, `radial_weighting`, `upper_atmosphere.type`, `transition_region_top_megameter`, `coronal_temperature_k` | Set the network and reference corona. Explicit `radial_weighting: null` disables the default SIREN radial weighting and affects initialization. |
| LTE windows | `id`, `line_ids`, `wavelength_bounds_vacuum_angstrom`, `radiance_scale`, `shell_height_bounds_megameter`, `lateral_halo_megameter` | Select spectral lines, their integration window, radiance units and spatial support. The MURaM Hinode MHS window covers the full physics shell. |
| LTE coefficient backend | `coefficient_backend`, `mapper_checkpoint` | Each window defaults to `exact_lte`. Select `nn_surrogate` with a compatible checkpoint to train through a frozen pointwise mapper. See the [training command and examples](muram-lte-coefficient-mapper-plan.md#standalone-training-command). |
| LTE integration | `depth_count`, `jitter_fraction`, `coarse_to_fine.enabled/fine_sample_count/uniform_weight_floor` | Set the coarse depth grid, training jitter and optional refinement. The MURaM Hinode Stokes-only run uses 16 coarse and 16 fine points. |
| Observation stream | `id`, `observation.type`, `directory`, `binning`, `channels_angstrom`, `selection.slit_slice.start/stop`, `acquisition_indices`, `validation_exposure_group` | Select an adapter, input data, spatial averaging and instrument-specific subsets. `muram_stored` is the active Hinode synthetic store reader. |
| Loading and calibration | `batch_size`, `validation_batch_size`, `validation_stride`, `preparation_workers`, `transmission_profile_directory`, `require_quality_zero`, `continuum_edge_samples`, `quiet_sun_max_fractional_polarization`, `quiet_sun_trim_quantiles`, `quiet_sun_continuum_trim_quantiles`, `minimum_quiet_sun_pixels`, `calibration_sample_limit` | Control training batches, validation reads, FITS preparation, filter transmission and quiet-Sun calibration. Stored MURaM Stokes rasters and synthetic HMI FITS already carry their radiometric calibration. Synthetic HMI still reads its filter response and checks quality. |
| Detector and Stokes loss | `data_term.type`, `weight`, `synthesis_window`, `instrument.type`, `spectral_psf.type/fwhm_angstrom/oversample/truncate_sigma`, `magnetic_azimuth_offset_deg`, `optimize_line_of_sight_velocity_correction`, `objective.type`, `continuum_normalization`, `stokes_weights.i/q/u/v`, `stokes_scales.I/Q/U/V`, `excluded_wavelength_windows_angstrom` | Apply the detector response and score the measured profiles. Scales divide the profiles before squaring. Weights multiply the component losses afterward. |
| EUV synthesis and loss | `response_resource`, `ray_samples`, `coarse_to_fine.enabled/fine_sample_count/uniform_weight_floor`, `objective.type`, `channel_weights[].channel_angstrom/weight` | Select the AIA response, integrate emission and score each channel. The dynamic SDO preset has a zero AIA fitting weight and still evaluates its EUV images. The energy preset fits AIA. |
| Standalone MURaM synthesis YAML | `instrument.type`, `spectral_psf.type/fwhm_angstrom/oversample/truncate_sigma`, `line_ids`, `observed_wavelength_angstrom` | Both column and ray synthesis use the Gaussian detector response, the two Fe I lines and all 112 detector wavelengths. These wavelengths are in air. |

## Physics, fitting and reporting

| YAML section | Parameters | Effect |
| --- | --- | --- |
| Physics | `vector_basis_matches_spatial_coordinates`, `equations.<name>.enabled/weight`, `coronal_energy.minimum_height_megameter`, `loss_start_step`, `loss_ramp_steps`, `robust_loss_delta` | Check the vector basis, select and weight residuals, restrict the energy closure by height, schedule or robustify the physics loss. The presets use MHS or momentum, induction, continuity, coronal energy, the vector-potential gauge, and selected top/side pressure, current or velocity conditions. Both Stokes-only presets omit this section. |
| Collocation | `volume_sampling`, `volume_points_per_step`, `upper_boundary_points_per_step`, `side_boundary_points_per_step`, `height_sampling_power`, `hard_example_enabled/count/start_step/jitter_time_hours` | Control spatial sampling, boundary counts and reuse of high-residual examples. The hard-example keys have the prefix `hard_example_`. Uniform-volume sampling draws points at constant density per cubic metre. |
| Physics validation | `validation_volume_points`, `validation_height_layers`, `validation_points_per_height`, `validation_upper_height_layers`, `validation_side_boundary_points` | Define deterministic validation samples. A shared training batch for volume and coronal equations still requires independent upper-domain validation samples. |
| Physics normalization | `length_m`, `time_s`, `normalize_force_balance`, `force_balance_pressure_floor_pa`, `normalize_boundary_current` | Set equation scales and optional normalization. MURaM Hinode MHS uses the raw model-unit force residual. |
| Potential boundary | `enabled`, `weight`, `ramp_steps`, `update_every_n_steps`, `photosphere.enabled`, `minimum_horizontal_field_gauss`, `start_step`, `ramp_steps`, `end_step` | This option computes potential-field targets and can apply a temporary photospheric prior. The potential needs a Stokes footprint, and a time-dependent run also needs distinct observation times. |
| Training | `optimizer`, `device`, `learning_rate`, `final_learning_rate`, `learning_rate_decay_steps`, `steps_per_epoch`, `max_epochs`, `max_steps` | Control optimization, learning-rate decay, sampling cadence and stopping. A limit of −1 disables that stopping criterion. |
| Diagnostic rendering | `ray_sampling.batch_size/max_pixels/max_profile_samples`, `slice_sampling.batch_size/longitude_points/latitude_points/radial_points`, `meridional_slice.enabled/longitude_deg`, `contribution_ray_count`, `dpi` | Bound ray and slice rendering and select the meridional cut. Contribution rays are an AIA diagnostic. |
| Logging | `logging.type/project/run_name/tags` | Configure experiment tracking. |

## Legacy and inactive settings

- **Compatibility.** Schema versions 1–4 and learned-radiation solver options are rejected. Older formal-LTE Stokes configurations can use `continuum_floor` with continuum indices for mean-based normalization, omit component scales, or use the Stokes `asinh_mse` transform. Replaying saved objectives uses these paths. The resource ID `legacy_lte_v2` still supplies the inversion’s atomic data and FALC reference atmosphere. AIA actively uses its own `asinh_mse` objective. `training.migrate_data_order` is an explicit checkpoint migration option.
- **Fixed conventions.** The schema accepts only `thermalized_continuum` for LTE `source_closure` and `atmosphere_outer_shell` for AIA `ray_end`. These labels allow older expanded configurations to round-trip. Each has a single implementation.
- **Conditional controls.** Fine-point settings apply only to enabled refinement. `height_layers_per_step` applies to grouped lower-volume training. Separate upper-volume training counts apply when upper equations need their own draw. Loss-balancer settings, potential-boundary schedules and their nested photospheric controls apply only when enabled. Vector-potential Hinode runs formerly requested a divergence penalty whose implementation returns zero by construction.
- **Loader controls.** `observation.loader.workers` sets the number of PyTorch worker processes per loader on each rank for native rasters and generic datasets. All inversion presets use four. `preparation_workers` defaults to four for FITS preparation and `training.reader_workers` limits concurrent native reads. Permanently zero-weight streams retain prepared data and checkpoint coverage for later fitting. Their training batches skip pixel reads and device transfers.
- **Defaults.** `transfer_precision: float32`, `qu_warmup_steps: 0`, a disabled gauge, empty `atmosphere_regularization`, enabled visualization and a training reference equal to the scene reference can be omitted in the maintained presets. Each remains available for configurations that need a different value.
